# SA BANK 1.0

Статический русскоязычный финансовый терминал Silent Ascend для GitHub Pages. Без сборщика, npm-зависимостей фронтенда, собственного сервера, закрытых API-ключей и подключения приватного кошелька к сайту.

## Статус поставки — прочитать перед публикацией

Это рабочая исходная реализация интерфейса и публичного слоя данных, **не утверждение о выполнении всех пунктов ТЗ**. Реальные финансовые значения не создаются вручную. Отсутствующие доказательства не подменяются демонстрационными результатами.

Включены:
- основные разделы ТЗ и расширенный блок финансовой статистики;
- публичные API TonAPI и DEX Screener, обновление раз в 60 секунд;
- реальные начальные снимки `data/latest.json` и `data/history.json` с временем и источниками;
- история через GitHub Actions, отдельные статусы данных, защита от смешивания несинхронных источников;
- интерактивные SVG-графики, периоды, расчёт изменения стоимости, ATH и просадки;
- алгоритм экспериментального индекса SA с проверками достаточности данных;
- пожертвования через TON URI, распознавание публичной метки в подтверждённых событиях;
- стена на GitHub Issues с обязательной модерацией и публикацией статического JSON;
- мобильное меню, копирование адресов, адаптивные таблицы, юридический дисклеймер;
- модульные тесты и дополнительный сценарий браузерной проверки.

Требуют действий владельца или дополнительной разработки:
1. Публикация в вашем GitHub-репозитории, настройка Pages, Issues и Actions.
2. Импорт оригиналов изображений. В этой поставке нет бинарных оригиналов приложений чата. Используется явно отмеченное резервное CSS-оформление и временный типографический favicon, не официальный знак SA.
3. Официальная ссылка VELLaR, URL сайта и Open Graph preview.
4. Подтверждённая классификация капитала, сделок выкупа и позиций VELLaR. Сейчас результаты стратегий показывают отсутствие подтверждения. Автоматического реестра доказанных выкупов в этой версии нет.
5. Подтверждённый учёт себестоимости и денежных потоков для инвестиционного P&L, TWR/MWR и коэффициента Шарпа. Эти вычисления намеренно не реализованы по предположениям.
6. Непересекающаяся история торговых объёмов для объёма за 7 дней, полная пагинация транзакций за всё время, учёт внешних DeFi-позиций/NFT и их доходности. Эти данные не выдаются за доступные.
7. Проверка публикации и отправки TON на реальных устройствах. Тесты не подписывают и не отправляют транзакции.

## Что вернули публичные API при подготовке

На 8 октября 2026 года проверка указанного адреса дала `balance: 0`, `status: nonexist`, пустые списки токенов и событий. DEX Screener вернул пустой список торговых пар SA. TonAPI вернул метаданные Silent Ascend, 4 держателя и `verification: blacklist`.

Это ответы провайдеров в момент проверки, а не вечные характеристики проекта. Точное время смотрите в JSON. Метка blacklist показана пользователю как предупреждение самого TonAPI; она не интерпретируется как самостоятельный юридический вывод SA BANK. Нулевая цена из API не считается достоверной котировкой. FDV не используется вместо рыночной капитализации.

**Проверьте правильность публичного кошелька и причины метки провайдера до публичного запуска.**

## Быстрая публикация на GitHub Pages

1. Создайте публичный репозиторий, например `sa-bank`, основная ветка — `main`.
2. Распакуйте архив. Загрузите **содержимое** проекта в корень репозитория, включая `.github` и `.nojekyll`. Не загружайте ZIP вместо файлов. `index.html` должен находиться непосредственно в корне.
3. В `config.js` укажите `repository: 'ВАШ_АККАУНТ/sa-bank'`. Адреса кошелька и SA уже заполнены.
4. В **Settings → Pages → Build and deployment** выберите **Deploy from a branch**, ветку **main**, папку **/(root)**.
5. Сохраните и дождитесь завершения публикации. Открывайте URL, который покажет GitHub, обычно `https://ВАШ_АККАУНТ.github.io/sa-bank/`.
6. Проверьте, что HTTP-ответ главной страницы — 200, CSS/JS/JSON не возвращают 404, показатели обновляются и меню работает на мобильном.
7. После изменений дизайна публикуйте коммит вручную от своего пользователя. Пути относительные: сайт работает и в подпапке репозитория, и на собственном домене.

В архиве нет выполненной публикации на GitHub, потому что репозиторий и права доступа не предоставлены.

## История через GitHub Actions

1. Разрешите Actions в репозитории.
2. В **Settings → Actions → General → Workflow permissions** разрешите запись содержимого. Workflow запрашивает `contents: write`.
3. Убедитесь, что правила защиты ветки разрешают запись боту. Иначе согласуйте безопасный процесс через pull request или отдельную ветку данных — текущая реализация пишет в `main`.
4. Запустите вручную workflow **«История публичного капитала»**.
5. Проверьте появление реального наблюдения в `data/history.json` и обновление `data/latest.json`.

По умолчанию планировщик запускается раз в час. GitHub Actions может задерживать или пропускать запуски; строгого SLA и минутного cron здесь нет. Автообновление браузера раз в 60 секунд — отдельный механизм. В неактивной вкладке опрос приостанавливается и возобновляется при возвращении.

**Важная особенность GitHub:** коммиты, созданные `GITHUB_TOKEN`, не запускают обычную повторную сборку Pages от ветки. Поэтому при заполненном `repository` сайт читает историю и стену напрямую из `raw.githubusercontent.com/.../main/data/`. Обычный браузерный CORS поддерживается; сайт по-прежнему размещён на Pages. Это не обход прав: читаются только публичные файлы. Не требуется PAT. Без `repository` читается копия из опубликованного сайта, которая обновится при следующем обычном деплое.

Для исторической точки сохраняются `t`, `portfolioAt`, `marketAt`, источники, статус полноты, стоимость и рыночные наблюдения. История до запуска не восстанавливается. Количество токенов сегодня не умножается на старую цену для создания фиктивной старой стоимости.

История не прореживается и не удаляется автоматически. Для многолетнего проекта потребуется разбивка на архивы и загрузка по периодам с сохранением проверяемых исходных данных. GitHub может приостанавливать scheduled workflows при длительном отсутствии активности; это следует контролировать.

Для добавления оригиналов из папки или ZIP:

```bash
pip install -q pillow
python3 scripts/import_assets.py /путь/к/оригиналам.zip
```

Импортёр понимает рекомендуемые имена из ТЗ и длинные имена большинства вложений из исходного сообщения. Предварительное назначение: горизонтальный арт с красным символом — Hero, сейф — пожертвования, интерьер с глобусом — стена. Подтвердите этот выбор; при другом назначении просто переименуйте файлы до импорта. Вертикальный fantasy-art не используется без отдельного указания места.

Цветовые фильтры не применяются. У логотипов удаляются только пустые внешние поля; форма и пропорции сохраняются. Hero/Donation/Wall перекодируются в WebP с качеством 95. Для SVG-оригинала скопируйте файл напрямую и измените путь в `config.js`; не нужно растрировать качественный SVG.

`assets/manifest.json` содержит список доступных материалов, например `{"available":["sa","bank","hero","donation","wall"]}`. Только перечисленные файлы запрашиваются. Это предотвращает 404 и битые изображения до импорта. Импортёр обновляет manifest автоматически.

Для favicon замените `href` в `<link rel="icon">` на официальный PNG и `type` на `image/png`. Текущий SVG — резервный типографический значок, не официальный знак. Для социальных сетей задайте **абсолютный** HTTPS URL `og:image` в `index.html`, добавьте `og:url` и при необходимости `twitter:image`. JavaScript не заполняет эти поля: социальные роботы обычно его не исполняют. Без предоставленного social-preview метатег изображения оставлен пустым, а не ведёт на несуществующий файл.

## Стена SA: реальная общая публикация, не localStorage-муляж

Хранилище пользовательских записей — GitHub Issues. Сайт не хранит токен GitHub и не имитирует отправку сообщения. localStorage используется только для дополнительной локальной задержки повторной отправки, не как общая база стены.

### Настройка

1. Включите Issues и укажите `repository` в `config.js`.
2. Создайте метку `sa-wall-approved`.
3. Назначьте ответственного модератора с правом выставлять метки.
4. Включите workflow **«Модерация стены SA»** с правами `issues: write`, `contents: write`.
5. Отправьте запись через форму сайта. Она откроет GitHub Issue с JSON. Пользователь подтверждает отправку на GitHub под собственным аккаунтом.
6. Прочитайте запись и только после проверки добавьте `sa-wall-approved`.
7. Workflow экспортирует последние 50 подходящих открытых записей в `data/wall.json`. Сайт обновляет стену раз в 5 минут.
8. Для удаления записи закройте Issue или снимите метку. Редактирование содержания снимает одобрение и требует повторной модерации.

### Защита

- Длина проверяется по Unicode code points, максимум 280. Пустое содержание, HTML-скобки и управляющие символы запрещены.
- Динамический контент выводится через `textContent`/DOM API. HTML пользователя не исполняется.
- На сайте и при публикации действует лимит одного сообщения от автора за 10 минут.
- Actions проверяет автора GitHub и отбирает только одобренные сообщения. Клиентская задержка не считается достаточной защитой.
- Окончательная защита от массового спама — модерация, механизмы GitHub, блокировка пользователей и при необходимости ограничения взаимодействия. Несколько аккаунтов могут обойти лимит на автора; абсолютной защиты от Sybil-спама не заявлено.
- Имя — подтверждённый логин GitHub. Декоративный аватар — первая буква логина. Фото профиля не требуется.
- Связь автора с адресом пожертвования не предполагается. Для неё в будущем нужна подпись кошелька/иной проверяемый механизм; непроверенные связи не отображаются.

Не публикуйте персональные или конфиденциальные данные: Issues и экспорт JSON публичны, старые версии могут остаться в истории Git.

## Пожертвования

Адрес получателя:
`UQDpHoPi5JHFruwdiKHCGO68gVaW4lKN0arzTAoMWVDWrjuv`

Кнопки создают стандартный `ton://transfer/АДРЕС?amount=НАНОТОН&text=...`. Используется BigInt: десятичная сумма переводится в nanoTON без ошибок двоичной арифметики. Разрешено до 9 знаков после запятой. Ноль, отрицательные значения, экспоненциальная запись и лишние параметры отклоняются.

Это deep link, **не TonConnect**. На устройстве нужен кошелёк, зарегистрировавший TON URI. На desktop без установленного обработчика копируйте адрес и добавляйте комментарий вручную. Нажатие кнопки не означает успешную транзакцию. Комиссия и подпись подтверждаются только в кошельке.

Для Donation Wall используется точный открытый комментарий `SA BANK DONATION`, успешный `TonTransfer`, совпадение получателя, положительная сумма и завершённое событие TonAPI. Самопереводы не считаются пожертвованием. Имя плательщика не выдумывается — показывается адрес. Обычный входящий перевод без метки не классифицируется как пожертвование.

Сейчас обрабатываются до 100 последних событий, не полная история всех пожертвований проекта. Для полноценного многолетнего Donation Wall требуется индексирование с пагинацией и архивом. TonAPI — индексатор, а не собственная проверка криптографических доказательств; пользователю доступна ссылка на explorer.

## Финансовая методология

### Три статуса происхождения

- `REAL`: показатель получен из публичного API.
- `CALCULATED`: расчёт на основании реальных данных.
- `UNAVAILABLE`: достоверного значения нет.

Пользователь видит русские обозначения: «Актуально», «Рассчитано», «Недоступно», «Обновляется» и «Устарело». Время рядом с финансовыми значениями — UTC. Периодовые изменения содержат обе исходные временные границы.

`receivedAt` — момент получения ответа API. Если API не сообщает время котировки, сайт не называет это временем рынка или блока. Данные кошелька и цен с разницей более 90 секунд не объединяются в полную оценку. При сбое в текущей сессии последнее успешное значение сохраняет исходный timestamp и получает отметку устаревания. При перезагрузке можно показать последний публичный `latest.json`.

### Стоимость и покрытие

Стоимость = сумма `количество × достоверная USD-котировка` всех обнаруженных TON и jetton-позиций. Неоценённый актив делает полную стоимость недоступной. Известная часть показывается отдельно. Настоящий нулевой баланс не является отсутствующим значением. Доли портфеля при нулевой общей стоимости не рассчитываются.

Обнаружение активов ограничено кошельком и ответом TonAPI. Заблокированные в сторонних протоколах активы, NFT, долговые обязательства, внешние адреса и офчейн-позиции не входят в эту оценку. Цена не учитывает проскальзывание при реализации всей позиции. Для бухгалтерской точности больших объёмов потребуются decimal-арифметика и отдельный учёт комиссий; UI использует IEEE-754 для оценочных USD-показателей, не для подписания сумм.

### Рыночные данные SA

Контракт идентифицируется полным нормализованным адресом, не тикером. Из пар DEX Screener берётся наиболее ликвидный доступный пул с SA как base token, положительной ценой и ликвидностью. Котировка, объём 24Ч, сделки и ликвидность явно ограничены этим пулом. `marketCap` выводится только если провайдер его сообщает; `fdv` не подменяет его. Количество держателей берётся отдельно из TonAPI.

Изменение капитализации строится из накопленных значений капитализации, не копируется из изменения цены. Объём 7Д не суммируется из перекрывающихся rolling-24h объёмов: нужен отдельный достоверный адаптер.

### Изменение стоимости и инвестиционная доходность — не одно и то же

Формулы из ТЗ реализованы именно для изменения стоимости:

`R = (Vкон / Vнач − 1) × 100%`

`ΔUSD = Vкон − Vнач`

При пополнении на 100 USD стоимость может вырасти на 100 USD без какой-либо инвестиционной прибыли. Поэтому интерфейс показывает это ограничение. Подтверждённый инвестиционный P&L не рассчитывается путём простого вычитания двух балансов.

24Ч = 1 день; 7Д = 7; 30Д = 30; 3М = 90; 6М = 180; 1Г = 365. Границы календарных лет — UTC. «Всё время» — с первого накопленного наблюдения, не с неизвестной даты создания проекта. При начальной стоимости 0 процент и CAGR недоступны.

Для сопоставления периода нужна реально записанная точка в пределах ±5 минут от искомой границы. Фактические timestamps доступны в интерфейсе. Интерполяция, экстраполяция и приблизительная годовая оценка не выполняются. При редком/неровном расписании Actions расчёт может остаться недоступным даже после календарного года. Для гарантированного календарного YTD нужна зафиксированная оценка возле 00:00 UTC 1 января; почасовой сбор на 17-й минуте по умолчанию её не гарантирует. Организуйте точный отдельный сбор или импорт подтверждённой оценки, не расширяйте молча окно допуска.

ATH и максимальная просадка относятся **только к накопленным наблюдениям стоимости**. Вывод средств может выглядеть как просадка; внутрипериодные экстремумы не восстанавливаются. Отображаются исторический пик, минимум и восстановление, если оно реально зафиксировано.

CAGR считается после полного года положительной истории по формуле из ТЗ и подписан как CAGR стоимости. Дневная волатильность — выборочное стандартное отклонение дневных логарифмических изменений стоимости при наличии 366 подходящих точек. Месячная и годовая — масштабирование на √30 и √365, а не обещание будущего риска. Денежные потоки из ряда не исключены.

Шарп, реализованный/нереализованный P&L и результаты стратегий недоступны без достоверного учёта себестоимости, потоков и ставки сравнения. Для продолжения разработки нужны доказанные реестры операций, политика комиссий/оценки и методика TWR либо MWR.

### Fear & Greed SA

Это открытый **экспериментальный индекс SA**, не общерыночный индекс и не методика Alternative.me. Параметры выбраны для данной реализации и требуют согласования и валидации владельцем проекта.

Нужны 31 дневное наблюдение одного и того же пула, положительные цена, капитализация и ликвидность, определённые объёмы и сделки. Допуск дневного отбора — ±2 часа. Изменение выбранного пула прерывает сопоставимость. Пустые значения не заменяются 50 или нулём.

Компоненты и веса:
- процентиль дневного логарифмического изменения цены — 20%;
- процентиль дневного изменения капитализации — 15%;
- процентиль rolling-24h объёма — 15%;
- процентиль отношения ликвидности к капитализации — 15%;
- обратный процентиль абсолютного дневного движения цены — 15%;
- процентиль числа сделок — 10%;
- доля покупок по количеству сделок, не по денежному объёму, — 10%.

Процентиль с учётом равных значений: `100 × (число меньших + 0.5 × число равных) / N`. Итог — взвешенная сумма, округлённая до целого от 0 до 100. Компонент амплитуды дневного движения — только прокси волатильности; малоликвидный рынок и wash trading способны искажать индекс.

0–24: крайний страх; 25–44: страх; 45–55: нейтрально; 56–75: жадность; 76–100: крайняя жадность. Для сравнения 3М назад также требуется предшествующее 30-дневное окно. До накопления полной истории соответствующий период недоступен.

## Проверки и ограничения запуска

`npm test` запускает модульные тесты: нормализация адресов/CRC, суммы TON, отличие нуля от отсутствия, отсутствие подмены FDV, полнота оценки, временная согласованность, периоды, просадка, CAGR, волатильность, Donation и защита текста стены.

Дополнительно:

```bash
pip install -q playwright
python3 -m playwright install --with-deps chromium
python3 tests/browser_check.py
```

Сценарий поднимает временный локальный HTTP-сервер, проверяет путь подпапки, меню, ширины экрана, URI пожертвования, ошибку HTML-текста, недоступность API и отсутствие локальных 404. Результаты и скриншоты сохраняются в `test-results/` (не публикуются по умолчанию).

Тесты не заменяют аудит безопасности, финансовый аудит, проверку фактической публикации GitHub Pages, мобильных Wallet-приложений и end-to-end работы GitHub Issues под вашим аккаунтом. Для запуска по исходному полному ТЗ сначала закройте перечисленные в начале недостающие пункты.
